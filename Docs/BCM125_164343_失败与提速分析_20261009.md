## 按需烧录和选项

系统设置的“测试失败处理”区域增加/调整三个选项，适用于 BCM125/250：

| 允许 TTL 烧录 | 每轮强制烧录 | 执行规则 |
| --- | --- | --- |
| 开 | 关 | 先读应用版本和通信状态；正确则跳过，只烧需要更新的 MCU。 |
| 关 | 关 | 正确固件可以测试；固件错误或无有效响应则明确失败，禁止模拟放行。 |
| 任意 | 开 | 版本相同也必须执行真实烧录，强制优先；启动前要求 TTL 及 HEX 文件。 |

“跳过烧录后的写入校验（verify）”默认关闭。打开后仅跳过 STM32 Bootloader 的逐块回读比对；仍执行 HEX 地址/数据解析、芯片 ID 检查、擦除、每块写入 ACK、复位、应用版本检查和后续功能测试。它不会跳过 E01/E02 或校准写入结果检查。

BCM125 在第8章正常上电后、第9章触碰 TTL/BOOT0/RESET 前执行预检：EXIT → SAFE R15 → REMOTE1/R0 → EXIT → REMOTE2/R0 → EXIT。SAFE 内部 CAN 异常不能靠烧 BCM 修复，预检失败会停止编程准备。需要烧录时先检查 HEX 和 TTL 配置，再进入原安全编程路径。

两颗 MCU 独立决策。健康 MCU 的 TTL 连接、BOOT0 和 RESET 编程动作显示为 SKIPPED，C01/C02 显示 EXISTING 及实际版本。两颗都无需烧录时，第9章共享编程准备和第10章烧录后的断电等待/上电操作也跳过；正式 CAN、版本、复位功能及后续电气测量仍执行。单独选择第10章而未执行预检时，保留原上电流程。

自动模式启动不要求 TTL 在线或 HEX 存在；发现坏版本才需要这些资源。用户界面显式传入强制选项；BCM250 的既有直接调用方式保留原构造参数兼容行为。
