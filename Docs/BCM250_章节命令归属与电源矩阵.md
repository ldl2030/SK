# BCM-250UP 各章节测试项、电源与命令归属矩阵

## 阅读规则

- 除 C01 的 TTL 烧录外，**运行期实际发送者都是测试 PC**：它通过 USB-B 串口把 ASCII 命令（尾随 `CR`）发送到 MBD Main MCU。本文的“发/读/写归属”表示**最终处理该命令的逻辑端**，不是说 MCU 主动向 PC 发起命令。
- `EXIT`：把会话切回 **MBD Main MCU** 终端；`REMOTE2`：经 MBD 的内部 CAN 桥进入 **DUT/BCM 的第一颗 MCU**终端。`DIAG ON` 作用于当前终端。
- BCM-250 是单控制器板：**只使用 `REMOTE2`，不使用 `REMOTE1`，也没有 BCM-125 的第二控制器/ST2 分支。**
- `Rxx` 是读取，`Wxx=value` 是写入，`ACT->FLASH` 是将当前 RAM 参数写入 Flash。虽然写入 Flash 的命令由 PC 发出，但执行/保存主体取决于当时的终端。
- **不要用 `VERB` 判定归属。** `Rxx` 与 `RxxVERB` 即使返回格式/确认信息不同，也不改变其执行端；必须以该命令前最近一次有效的 `EXIT` 或 `REMOTE2` 判定目标。
- **SAFE 与 DUT MCU 不能混为一类。** Rev.5 仅证明 `REMOTE2` 进入“BCM/DUT 第一颗 MCU”终端，没有给出可由 PC 单独切入的 SAFE 固件终端。D02 是 PC 在 MBD 终端发送 **`R15`**，由 MBD 读取 SAFE 从机的内部 CAN 应答时间；不是 PC 直接向 SAFE 固件发送的命令。若 SAFE 有独立命令表，需要以其协议补充，不能从 `R15` 反推。
- C01 的烧录对象是 **DUT MCU 的 Bootloader 与应用固件**：烧录器经 TTL 向 Bootloader 发送擦除/下载/校验协议；这与 DUT 应用固件经 `REMOTE2` 接收 `Rxx/Wxx` 是不同阶段、不同链路。
- 下表中“ANS”=电源 C（MPS/DUT 275 V 电源，经高功率继电器 Y7/RL4）；“VBUS”=恒辉 A；“String”=恒辉 B；“负载”=KUNKIN 7303。

## 终端与命令速查

| 会话位置 | 路由命令 | 命令由谁处理 | BCM-250 内的常见用途 |
|---|---|---|---|
| MBD Main MCU 终端 | `EXIT` 后 | MBD Main MCU | 板级复位、MPS 侧继电器/模拟输入控制、读取 MBD 侧状态 |
| DUT MCU 应用固件终端 | `REMOTE2` 后 | BCM-250 DUT MCU | 读取/写入 BCM ADC、状态机、校准量、CCB/MOS、身份信息 |
| DUT MCU Bootloader | TTL + BOOT0 + RESET | DUT MCU Bootloader | C01 接收烧录器的擦除、写页、校验、启动等烧录协议；不是 `Rxx/Wxx` 协议 |
| SAFE 固件 / SAFE 节点 | 本流程无独立 Remote | 当前仅通过 MBD `R15` 间接观测 | 报告 SAFE 内部 CAN 应答时间；是否有独立读写命令尚无协议证据 |
| 诊断模式 | `DIAG ON` | 当前终端 | 打开当前端的诊断命令权限；若在 `EXIT` 后即 MBD，若在 `REMOTE2` 后即 DUT MCU 应用固件 |
| 固件烧录 | TTL + BOOT0 | 外部烧录器/DUT MCU Bootloader | 不是 Remote 命令；MBD 仅负责前后的 `W86` 复位 |

## 命令方向：谁“发”给谁

| 场景 | 命令/数据方向 | 代表内容 | 归类时应写成 |
|---|---|---|---|
| MBD 本地命令 | 测试 PC → USB-B → MBD Main MCU | `W86`、`W91`、`W95`，以及 MBD 侧 `R68/R69/R81`；`W101` 为当前代码的额外站点命令 | **PC 发给 MBD；MBD 执行/回读** |
| DUT 应用固件命令 | 测试 PC → USB-B → MBD → `REMOTE2` → DUT MCU | DUT 的 `R0/R10/R42…`、`W67/W69/W71/W75`、校准和身份字段 | **PC 经 MBD 路由发给 DUT MCU；DUT MCU 执行/回读** |
| DUT 应用固件响应 | DUT MCU → MBD → 测试 PC | 所有 `Rxx` 的返回值、状态机变化、CAN 状态被主控汇总后的结果 | **DUT MCU 回传数据**，不是 DUT MCU 主动发送一条 `Wxx` 命令 |
| DUT MCU 烧录 | 外部烧录器 → TTL → DUT MCU Bootloader；Bootloader → 烧录器 | C01 的擦除、下载、校验、完成应答 | **烧录器向 DUT Bootloader 发协议；DUT Bootloader 回应**；PDF 给出的工具行为为 `--erase all --download bcm_250_v5.hex --v`，MBD 仅用 `W86` 和 BOOT0 辅助进入该模式 |
| SAFE 状态上报 | SAFE 节点 → 内部 CAN → MBD；测试 PC 以 `R15` 读取 | D02 SAFE 内部 CAN 从机应答时间 | 当前只能标为 **MBD 读 SAFE 上报状态**；不能把它标成“PC 直接向 SAFE 发命令” |

因此，“DUT MCU 发的命令”在这套测试记录里应拆成两种：**DUT 回传应用固件的读结果**，以及 **DUT Bootloader 回应烧录器**。现有流程没有给出 DUT MCU 主动向测试 PC 下发独立 `R/W` 命令的报文定义。

### 归属判定规则

1. 最近一次为 `EXIT`：后续 `Rxx/Wxx/DIAG ON` 由 **MBD Main MCU 固件**处理，直到下一次 `REMOTE2`。
2. 最近一次为 `REMOTE2`：后续 `Rxx/Wxx/DIAG ON/ACT->FLASH` 由 **DUT/BCM MCU 应用固件**处理，MBD 只负责 CAN 转发。
3. `RxxVERB` 的归属与同号 `Rxx` 完全相同；它不能作为 SAFE、MBD 或 DUT 的判据。
4. **SAFE 固件**在这份规程中没有 `REMOTE` 入口或直接 `R/W` 协议。`R15`（或实现中的 `R15VERB`）是 MBD 固件读取 SAFE CAN 从机应答时间，命令处理者仍是 MBD。

## 关键安全边界

1. String 输出使能前：String 电源必须 OFF，且高功率继电器 **Y1/Y3/Y6 三路均已闭合**；结束时先关输出再断开三路。
2. RL4/ANS 断电顺序：**先关闭 ANS 输出，再断开 Y7/RL4**。
3. `W86`、`W91`、`W95`（以及当前代码扩展的 `W101`）必须在 **MBD Main MCU 终端**执行；`W67`、`W69`、`W71`、`W75` 及校准/身份字段必须在 **`REMOTE2` 的 DUT MCU 应用固件终端**执行。
4. 章节 9 的 TTL 烧录路径和运行期 USB-B/MBD 通信是两条不同路径，不能将 TTL 烧录器当作 `REMOTE2` 通信通道。

## Rev.5 PDF 与当前 TestPlatform 的差异 / 记录方式

本矩阵的章节表按 Rev.5 PDF 的原始命令记录。`VERB` 仅作为当前实现的返回/确认形式记录，**不构成命令归属差异，也不影响 MBD/DUT 分类**。实际固件版本字符串和 PDF 未列的站点扩展仍须以连机响应确认。

| 项目 | Rev.5 PDF 原文 | 当前实现 / XML | 处理结论 |
|---|---|---|---|
| D02 SAFE CAN | MBD 终端读 `R15` | `R15VERB` | 同属 **MBD 端**；`VERB` 不改变 SAFE/MBD/DUT 归属，只影响当前实现采用的确认/返回形式 |
