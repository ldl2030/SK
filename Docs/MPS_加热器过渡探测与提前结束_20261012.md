# MPS 加热器过渡探测与提前结束

适用 MPS-125、MPS-250；2026-10-12。

## 问题与证据

`ActivityLog_20261012_145015_145357.txt` 五个 CH17 稳定窗口合计 39.806 秒。两次开启在约 3.6 秒时因 `+9.90000000E+37` 放弃提前测量，随后各约 6.4 秒不再探测；10 秒后原 1V 量程正式反馈测量成功。开启前反馈约 8～9V，而过渡探测直接使用稳态 1V 量程，过渡超量程是优先验证的原因，日志尚不能直接证实。

## 本次修改

- 两次开启在最短等待后，用 10V 量程单次测量反馈；未进入对应 XML 电压范围时继续探测，进入后再执行原量程、原采样数、原间隔的两轮完整测量。
- 过渡探测值只决定是否开始完整测量，不能缓存为正式结果。
- 以 `DaqInvalidMeasurementException` 区分仪器数值无效/超量程与格式错误、通信超时等错误；数值无效重置两轮连续性并在原预算内重试，其他异常仍回退原等待。
- 两轮电压反馈合格且电压、电流均稳定时提前结束。稳定但超限的电流不会强制等满；缓存的电流仍保留真实值和 NG 判定。L11 XML 范围未修改。
- 未就绪或超过原预算时不复用探测结果，正式行重新测量；用户取消仍传播。在途 I/O 及恢复操作结束后才允许后续测量。
- 共同逻辑位于 `Sequences/SK/Common/SKBaseSequence.Stability.cs`。BCM 两套不调用这五个加热器窗口，不套用 MPS 接线或时序。

## 验证与下次实测

软件回归覆盖 8.9V→无效值→正常反馈、首次完整平均和逐次回退均无效后的恢复、两轮确认、1V 正式量程、缓存一次消费、稳定超限电流仍 NG、持续未就绪回退，以及预算和取消。要求四套回归全部通过。

本次验证：Visual Studio MSBuild Debug / Any CPU 构建通过；BCM-125（956 步）、BCM-250（598 步）、MPS-125（231 步）、MPS-250（211 步）四套回归均返回 0。输出程序已更新到 `bin/Debug/TestPlatform.exe`。验证使用模拟仪器，未启动真实工装。

新日志包含“开启过渡探测”及反馈值、量程、窗口累计耗时，可以定位首次进入目标范围的时间。将两次开启实际窗口、五窗口总耗时与 10.012/10.002/39.806 秒基线比较；实际节省秒数需新硬件日志确认。最终确认仍执行两轮完整测量，未减少采样数或采样间隔。
