# BCM-125 MCU1 烧录诊断（2026-10-09）

MCU1 可以正常运行应用并通过 CAN 通信，但在独立 TTL/UART 烧录链路上没有同步响应。现场复现优先指向 MCU1 专用 J4 串口路径（接线、继电器触点、夹具接触、TX/RX/GND），其次是 BOOT1 等启动引脚电平。现有软件证据无法确定具体断点，也不能仅凭应用停止响应认定 MCU1 已进入 ROM Bootloader。

## 原始故障

- `bin/Debug/Logs/ActivityLog_20261009_094925_095123.txt`：09:49:57.267 发送同步字节 `0x7F`，09:49:59.822 超时（2500 ms），未执行擦除、写入。
- 同次 MCU2 返回 Bootloader 版本 `0x22`、芯片 ID `0x410`，完成 131072 字节写入和全部回读校验。
- 09:47 的另一份日志同样为 MCU1 同步超时、MCU2 写入及校验成功，故障具有重复性。

## 现场实测

用户将程序暂停在 MCU1 的 `W86=0` 已执行、C01 烧录尚未执行的位置。诊断只执行握手、查询、复位和已定义的低压编程通路切换，没有擦除、烧录或修改校准参数，没有更改电源设定。

- USB 枚举正常：TTL CH340 COM20、MBD COM24、DAQ COM16、工装共享总线 COM12、ANS COM23。
- ANS 回读为 139.8 V、0.030 A；DI7=0（下压到位）、DI8=0（急停未触发）。
- DAQ 返回 `ROUT:CLOS? (@305,306) = 1,0`；错误队列为 `+0,"No error"`。
- 工装站1寄存器回读：MCU1 路由为 Y3/Y4/Y5=1、Y6/Y7/Y8=0；MCU2 路由为 Y3/Y4/Y5=0、Y6/Y7/Y8=1。
- 这些回读确认控制状态；不等于芯片端电平或继电器触点导通的实测。

| 测试 | 结果 |
|---|---|
| MCU1，用户当前暂停状态，115200 8E1 | 同步超时 |
| MCU1，DAQ305，复位保持/释放后等待各500 ms，115200 8E1 | 同步超时 |
| MCU2，DAQ306，相同时序，115200 8E1 | 握手成功，GET ID 原始回复 `79-01-04-10-79`，ID=0x410 |
| MCU1，DAQ305，等待各1000 ms，9600 8E1 | 同步超时 |
| MCU1 串口路由，改用DAQ306 | 同步超时 |
| MCU2 串口路由，改用DAQ305 | 同步超时 |

互换 BOOT 通道未修复 MCU1，且使 MCU2 失去响应，没有证据支持将305/306映射对调。共同 TTL 适配器、协议实现和固件文件已由 MCU2 成功结果验证；简单延长等待、降低波特率未解决 MCU1。

## 应用与启动模式对比

通过 MBD 的 `REMOTE1/REMOTE2` 分别读取 `R0`（固件版本）和 `R10`（运行时间），每次查询后发送 `EXIT` 回到 MBD 根终端。

| MCU | BOOT继电器 | R0 | 复位后的R10 |
|---|---|---|---|
| MCU1 | DAQ305闭合 | 无响应 | 无响应 |
| MCU1 | BOOT继电器断开 | `stcu_UP125_V8` | 2.126 s |
| MCU2 | BOOT继电器断开 | `stcu_UP125_V8` | 2.145 s |
| MCU2 | DAQ306闭合 | 无响应 | 无响应 |

MCU1 应用存在且可运行，供电足以支持运行，复位操作有实际效果，BOOT 控制改变了应用响应状态。正常 CAN 通信与 TTL 烧录使用不同接口，因此“可以通信但不能烧录”并不矛盾。BOOT闭合后应用停止响应仍不能区分 ROM 启动与错误启动模式。

对于 STM32F10xxx，ROM Bootloader 的启动条件与USART引脚应按实际芯片型号核对；AN2606 给出该系列的 BOOT0/BOOT1 条件和 USART1 硬件要求。若以后具备现场测量条件，应检查芯片侧 BOOT0、BOOT1、NRST，以及 PC 的 `0x7F` 是否到达 MCU RX、MCU TX 是否产生 `0x79`、该应答是否到达适配器 RX。由此可区分发送路径、接收路径和启动模式问题。

参考：[ST AN2606](https://www.st.com/resource/en/application_note/an2606-introduction-to-system-memory-boot-mode-on-stm32-mcus-stmicroelectronics.pdf)。
